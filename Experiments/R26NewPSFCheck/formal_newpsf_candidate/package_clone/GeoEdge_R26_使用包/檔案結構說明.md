# GeoEdge R26 封包結構說明

這份封包是 **正式 `R26 / r26_sm035` 重現與使用封包**。  
它同時兼顧兩件事：

- 一般使用者可以輕鬆推論
- 需要時可在 package 內重現正式 `R26` winner 的歷史訓練效果

## 1. 你通常只需要知道哪些入口

| 我想做什麼 | 入口 |
|---|---|
| 第一次打開 | `START_HERE.bat` |
| 看示範推論 | `RUN_DEMO_INFERENCE.bat` |
| 跑外部資料 | `RUN_CUSTOM_INFERENCE.bat` |
| 做 quick smoke | `RUN_QUICK_TRAIN.bat` |
| 重現正式 R26 訓練 | `RUN_FULL_TRAIN.bat` |

## 3. 哪些是正式 R26 重現核心資產

- 正式 winner 權重：
  - `內部檔案\weights\r26_sm035_best_tradeoff.pth.tar`
- 正式 seed checkpoint：
  - `內部檔案\weights\r25_sw010_seed_best_tradeoff.pth.tar`
- 正式舊 PSF：
  - `內部檔案\PSF_Fitting\Crop_circle_FreqFiltered\Fits\PSF_fitted_2D_FOVstack.mat`
- 正式 recipe：
  - `內部檔案\formal_r26_recipe.json`

## 4. Training_Data 為什麼分成兩層

### 一般使用層

- `內部檔案\Training_Data\tra_src_ring`
- `內部檔案\Training_Data\tra_lbl_ring`

用途：

- demo 推論
- quick smoke
- 一般包內基本操作

### 正式重現層

- `內部檔案\Training_Data\generated_convolved`
- `內部檔案\Training_Data\generated`

這裡不是全量歷史資料，而是只保留正式 `r26_sm035` 實際依賴的 selected stage 子集。  
`RUN_FULL_TRAIN.bat` 會固定使用這一層。

## 5. wrapper 與底層腳本怎麼分工

### 底層腳本

位於：

- `內部檔案\Model\GeoEdgeAlignSR_v1_Train_v5_NoCoord_return_v2_SimpleTest.py`
- `內部檔案\Model\GeoEdgeAlignSR_v1_Infer_v5_NoCoord_return_v2_SimpleTest.py`

這些腳本維持和主線同步，不直接承擔「正式 R26 recipe 管理」。

### wrapper

位於：

- `內部檔案\GeoEdge_R26_FormalTrain.ps1`
- `內部檔案\GeoEdge_R26_FormalInfer.ps1`

它們負責：

- 讀取 `formal_r26_recipe.json`
- 解析 package 內相對路徑
- 將正式 `R26` 固定配方套到 train / infer 腳本

因此，使用者看到的是簡單入口；歷史 recipe 的複雜度被固定在 wrapper 與 manifest 裡。

## 6. 輸出結果怎麼解讀

- `輸出結果\推論結果\`
  - 正式 `r26_sm035` 推論輸出
- `輸出結果\訓練結果\`
  - 正式 `R26` 重現訓練輸出
- `輸出結果\訓練結果\_smoketest\`
  - quick smoke 產物，不可和正式歷史重現混為一談

## 7. 這份封包故意不做什麼

- 不包含整個 `round26` candidate sweep / decision pipeline
- 不承諾在 package 內重跑所有歷史 round26 候選
- 不把 smoke / quick 結果包裝成正式 `R26` 效果

這份封包只承諾：

**正式 `r26_sm035` winner 的使用與重現。**
