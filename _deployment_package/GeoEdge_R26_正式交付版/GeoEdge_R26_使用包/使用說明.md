# GeoEdge R26 使用說明

## 這個封包是幹嘛的？

這個封包封裝了 GeoEdge 影像對齊超解析度模型的 **R26 正式版本（`r26_sm035`）**，
讓你不需要了解內部程式細節，就能直接做兩件事：

1. **直接拿來推論**：把一張或一批影像丟進去，讓模型輸出對齊後的結果
2. **重新訓練**：用與 R26 完全相同的歷史 baseline 條件，從頭跑一次完整訓練，取得新的權重

這個封包**不是**通用的訓練沙箱，它不支援任意修改超參數或自由實驗。
它只保證兩件事：正式 `r26_sm035` 的使用，以及完整重現 R26 的重新訓練。

---

## 封包的檔案長什麼樣子？

打開封包資料夾，你會看到這些東西：

```
GeoEdge_R26_使用包\
│
├── START_HERE.bat              ← 第一次用：從這裡開始
├── RUN_DEMO_INFERENCE.bat      ← 跑示範推論
├── RUN_CUSTOM_INFERENCE.bat    ← 對自己的影像推論
├── RUN_FULL_TRAIN.bat          ← 重新訓練
├── INSTALL_GPU_PATCH.bat       ← 安裝 GPU 加速
│
├── 使用說明.md                 ← 就是這份文件
│
└── 內部檔案\                   ← 不需要手動進去，各入口會自動使用
    ├── weights\                ← 模型權重（推論用 + 訓練起點 seed）
    ├── Model\                  ← 推論與訓練 Python 腳本
    ├── PSF_Fitting\            ← 鏡頭 PSF 參數（已封存在模型內）
    ├── Training_Data\          ← 訓練用資料（共 10 個 stage 子集）
    ├── Demo_Input\             ← 示範輸入影像
    ├── formal_r26_recipe.json  ← 記錄 R26 所有正式訓練超參數
    └── GeoEdge_*.ps1           ← 背後的自動化腳本（不需手動執行）
```

> `輸出結果\` 資料夾不一定預先存在，第一次執行時會自動建立。

## 第一次使用：先從這裡開始

### 雙擊 `START_HERE.bat`

這個步驟是必要的，只需要做一次。
它會自動完成環境偵測與初始化，包括：

1. **找 Python**：依序搜尋本機 Windows Python、系統 PATH、常見安裝路徑
2. **建立虛擬環境**：在 `內部檔案\.venv\` 建立獨立的 Python venv，不影響系統環境
3. **安裝套件**：自動安裝所需套件（`torch`、`torchvision`、`scipy`、`opencv`、`h5py` 等）
4. **偵測 GPU**：如果有 NVIDIA GPU，會自動安裝對應 CUDA 版本的 PyTorch（CUDA 11.8 / 12.6 / 12.8）
5. **顯示選單**：環境就緒後，顯示可用操作的互動選單

完成後，之後每次執行其他 `.bat` 檔就不需要再做設定了。

> **注意：** 第一次執行需要網路連線（用來下載 PyTorch 等套件）。
> 如果你的機器沒有網路，請見下方「離線 GPU 補丁」章節。

## 推論：怎麼跑出結果

### 方式一：示範推論（最快上手）

**雙擊 `RUN_DEMO_INFERENCE.bat`**

系統會自動：
- 讀取封包內預置的示範影像：`內部檔案\Demo_Input\VisionTop_20251029182653732.bmp`
- 載入正式 `r26_sm035` 權重：`內部檔案\weights\r26_sm035_best_tradeoff.pth.tar`
- 從權重檔內讀取 PSF 參數（鏡頭光學特性，已封存在模型內，不需額外提供）
- 執行推論，輸出結果

**結果輸出到：`輸出結果\推論結果\`**

這是最快驗證封包能不能正常運作的方式。如果這裡能跑出結果，基本環境就沒問題。

---

### 方式二：對自己的影像推論

**雙擊 `RUN_CUSTOM_INFERENCE.bat`**

系統會提示你輸入**影像資料夾的路徑**。
把你想推論的 `.bmp`（或支援的影像格式）放在同一個資料夾裡，輸入該路徑後按 Enter。

系統會自動：
- 對資料夾內的每張影像執行推論
- 套用相同的 `r26_sm035` 權重與 PSF 參數
- 輸出結果

**結果輸出到：`輸出結果\推論結果\`**

> **重要提醒：** 推論時請**直接走這兩個 `.bat` 入口**，
> 不要手動去修改 `內部檔案\Model\` 下的 Python 腳本預設值。
> 所有正式參數已由 wrapper 自動設定好。

## 訓練：基於歷史 R26 baseline 的完整重新訓練

**雙擊 `RUN_FULL_TRAIN.bat`**

這個入口會用 R26 的歷史訓練條件，完整跑一次 60 個 epoch 的訓練。
你不需要手動設定任何參數，wrapper 會自動從 `formal_r26_recipe.json` 讀取所有正式設定。

### 訓練用了哪些東西？

| 項目 | 說明 | 路徑 |
|---|---|---|
| 起點 seed 權重 | 從上一輪（R25）最佳權重開始，不是從隨機初始化開始 | `內部檔案\weights\r25_sw010_seed_best_tradeoff.pth.tar` |
| PSF 參數 | 鏡頭光學特性，訓練時用來做卷積模擬 | `內部檔案\PSF_Fitting\Crop_circle_FreqFiltered\Fits\PSF_fitted_2D_FOVstack.mat` |
| 訓練資料輸入 | 經過 PSF 卷積處理的模擬低解析影像 | `內部檔案\Training_Data\generated_convolved\` |
| 訓練資料標籤 | 對應的原始高品質標籤影像 | `內部檔案\Training_Data\generated\` |
| 訓練配方 | R26 的所有超參數（learning rate、loss 權重等） | `內部檔案\formal_r26_recipe.json` |

### 訓練資料涵蓋哪 10 個 stage？

封包內只保留 `r26_sm035` 實際依賴的 10 個 stage 子集（不是全量歷史資料）：

| Stage | 類型 |
|---|---|
| stage_08 | annulus_focus（環形聚焦）|
| stage_09 | annulus_non_overlap（環形不重疊）|
| stage_10 | annulus_overlap（環形重疊）|
| stage_14 | annulus_edge_defect_focus（邊緣缺陷聚焦）|
| stage_15 | annulus_sparse_clean（稀疏清潔）|
| stage_16 | annulus_sparse_defect_clean（稀疏缺陷清潔）|
| stage_23 | annulus_gmf_sequence_mid_clean（序列中段清潔）|
| stage_24 | annulus_gmf_sequence_mid_defect（序列中段缺陷）|
| stage_27 | annulus_gmf_sequence_midwide_clean（序列中寬清潔）|
| stage_28 | annulus_gmf_sequence_midwide_defect（序列中寬缺陷）|

> stage 23–28 為序列資料，訓練時會同時用單幀與序列兩種方式學習。

### 訓練的關鍵設定

- **總 epoch 數**：60
- **固定亂數 seed**：`1261620`（deterministic 模式開啟，結果可重現）
- **起點**：載入 R25 seed 權重，epoch 從 0 重置，optimizer 狀態保留
- **最佳模型選取**：訓練過程中自動依據邊緣寬度與高頻指標的平衡點記錄最佳 checkpoint

### 結果輸出到哪裡？

**`輸出結果\訓練結果\`**

訓練期間每個 epoch 都會記錄 checkpoint 與指標，你可以從中自由挑選最佳權重。

## GPU 加速

### 有網路的機器（預設行為）

`START_HERE.bat` 第一次執行時，如果偵測到 NVIDIA GPU（透過 `nvidia-smi`），
會自動判斷你的 CUDA 版本，然後從 PyTorch 官方下載對應的 GPU 版套件：

| 偵測到的 CUDA 版本 | 安裝的 PyTorch 版本 |
|---|---|
| CUDA 12.8 以上 | `cu128` |
| CUDA 12.6–12.7 | `cu126` |
| CUDA 11.8–12.5 | `cu118` |
| 未偵測到 NVIDIA GPU | CPU 版本 |

設定好之後，後續每次推論與訓練都會自動使用 GPU（`cuda:0`）。

### 沒有網路 / 離線環境（GPU 補丁）

如果你的機器沒有網路，或需要在無網路環境使用 GPU：

**雙擊 `INSTALL_GPU_PATCH.bat`**

這個入口會自動在封包的**上一層目錄**尋找 `GeoEdge_R26_GPU??` 這個資料夾（GPU patch 包）：

```
上一層資料夾\
├── GeoEdge_R26_使用包\         ← 就是這個封包
└── GeoEdge_R26_GPU??\          ← 離線 GPU patch 包（需另外取得）
```

如果自動偵測失敗，它會請你手動輸入 patch 資料夾的路徑。

> **備用方案**：Docker / WSL 可作為最後手段，但正常情況下不需要用到。

## 訓練資料的結構說明

`內部檔案\Training_Data\` 有四個資料夾，用途各不同：

| 資料夾 | 用途 |
|---|---|
| `tra_src_ring\` | Demo 推論等基本操作的備用資料（ring 格式輸入） |
| `tra_lbl_ring\` | 對應的 ring 格式標籤 |
| `generated_convolved\` | 完整重新訓練的模型**輸入**（已做 PSF 卷積的模擬低解析影像） |
| `generated\` | 完整重新訓練的模型**標籤**（原始高品質影像） |

一般使用者不需要直接碰這些資料夾，各入口自動使用對應的那層。

## 背後的執行流程（給想了解更多的人）

當你雙擊任何一個 `.bat` 檔，背後發生了什麼：

```
你雙擊 .bat
  ↓
呼叫 GeoEdge_AutoLauncher.ps1
  ↓
自動偵測：本機有沒有可用的 Python？
  ├─ 有 → 走 Native 路徑（GeoEdge_NativeLauncher.ps1）
  │         └─ 找 .venv → 裝套件 → 偵測 GPU → 執行 Python 腳本
  └─ 沒有 → 走 Docker/WSL fallback 路徑
```

這個偵測邏輯讓同一套封包可以在有/無 GPU、有/無網路、多種 Python 安裝方式的機器上都能運作。

## 建議的操作順序

1. **雙擊 `START_HERE.bat`** → 確認環境偵測與初始化正常，看到主選單
2. **雙擊 `RUN_DEMO_INFERENCE.bat`** → 確認推論能正常跑出結果
3. 有自己的影像要跑時，**雙擊 `RUN_CUSTOM_INFERENCE.bat`**，輸入影像資料夾路徑
4. 真的需要重現 R26 訓練時，**雙擊 `RUN_FULL_TRAIN.bat`**

## 使用注意事項

- **不支援自由實驗**：這個封包只承諾正式 `r26_sm035` 的使用，以及基於歷史 R26 baseline 的重新訓練。不支援任意修改 recipe 或 hyperparameter 的自由實驗
- **不要修改 Python 腳本**：推論和訓練請走 `.bat` 入口，不要直接修改 `內部檔案\Model\` 下的 Python 腳本預設值，否則正式參數會被覆蓋
- **路徑不要包含特殊字元**：封包路徑中如果有特殊字元（例如 `&`、`%`）可能會造成 BAT 腳本解析問題，建議放在路徑單純的位置
