# 最後保存版本的發布順序

本頁是本次保存工作的交付檢查，不代表目前已完成。所有必要批次、來源差異與實際恢復仍須完成；原D工作分支、索引、論文、正式模型與訓練資料保持原樣。

## 來源與資料的界線

- `ALL_RESEARCH_CONTENT_HASHED.json`證明當次完整來源內容已核對，不等於全部已上傳。
- 每批必須有完整的GitHub下載、寫出、內容核對及隔離讀取收據；清單、物件集合和壓縮分段須逐項相同。
- 舊398份交付批次已因私人工具備份撤下而作廢；只用修正後396份批次。排除政策同時核對路徑與相同內容，原私人物件留本機。
- 本機與目前引用的H資料最後要再查新增／變動／缺件，不能把數小時前的核對當作永遠不變。H檢查限原登記目標，不掃整個H槽，也不讀另一專案同名R152結果。
- 22個未尋回來源版本、9個早期R13總分公式缺件及原有失敗必須保留。保存完成不能冒稱重跑所有歷史GPU訓練。

## 固定來源，避免完成證據互相牽動

先在候選程式版本中寫清當次範圍、各輪判讀與最後交付證據的固定連結，再固定一般程式清單。最終完成收據放進固定GitHub保存版本的附件，避免為了把完成收據寫回程式而改掉已驗證的來源清單，讓總恢復索引失效。

候選程式中的保存狀態應清楚寫為「固定來源快照；完成事實見最後交付收據」，不能沿用容易混淆的即時進度布林值。完成與否以實際取得的最後總收據認定。既有較早收據保留原先時間與驗證範圍，不改寫成全專案完成。

## 總位置與每份附件必須綁定

所有資料批次完成後，用固定來源版建立總恢復索引，再從該總圖產生各新保存版本的最終原位置清單。不要發布暫存物件位置，也不要把初步組裝清單當成全域位置已確認。 各批最終證據另列實際格式讀取結果及原有失敗：檔案完整相同、模型可載入、陣列結構可讀與影像可解讀分別記錄，不能互相代換；陣列結構檢查不宣稱所有數字有限或已重算。

```powershell
python Tools/build_project_restore_index.py --root FIXED_SOURCE --operation OP --output MASTER_DIR
python Tools/bind_verified_collections_to_master.py --operation OP --master-index MASTER_DIR/MASTER_RESTORE_INDEX.json --output BOUND_DIR
```

`--review-paths-only`只可提早找來源位置或缺件問題，永遠不產生可恢復的總索引。較早保存清單另放歷史位置，不覆蓋固定程式副本自己的清單；目前H引用優先，較舊不同結果另留歷史。

新保存版本在仍為私人草稿時，先上傳已綁定的最終清單與驗證摘要，再用伺服器實際附件逐份核對。全部已取回的物件才能發布；舊已發布版本不覆寫。

附件核對使用[GitHub官方的完整逐頁附件介面](https://docs.github.com/en/rest/releases/assets#list-release-assets)，不只讀一頁或推測附件名稱。可先對一份完成的資料批次檢查：

```powershell
python Tools/verify_project_release_assets.py --repo rio10255254/GMM_2_Final --manifest COMPONENT_MANIFEST --tag COMPONENT_TAG --allow-draft --report PRELIMINARY_SERVER_CHECK.json
```

全部新資料版本發布且固定來源後，再以總索引檢查所有原附件的大小、內容身分、完成狀態及新版本來源：

```powershell
python Tools/verify_project_release_assets.py --repo rio10255254/GMM_2_Final --master-index MASTER_DIR/MASTER_RESTORE_INDEX.json --expected-new-source-commit FIXED_SOURCE_COMMIT --report FINAL_SERVER_CHECK.json
```

此命令的總索引模式會拒絕未發布版本與位置仍待確認的清單。伺服器附件核對不能取代先前實際下載與寫出檔案的核對。

## 最後總版本先取回測試，再宣稱完成

將總索引、所有跨版本位置清單、較早程式對應及原ZIP分段索引打成總恢復附件，先放入最後保存版本的私人草稿。程式來源已固定；由GitHub取得該來源和草稿總附件，在另一個自有工作位置驗證：

1. 固定一般程式全部符合來源清單；總附件的所有內部檔案也符合其內容身分。
2. 代表性恢復跨過新模型、完整數字、影像、原交付包及較早程式版本，實際落在最終原位置；原D／H研究來源不可讀。
3. H目前引用與較舊結果分開，共用位置能接回各輪，11個專案內引用能建立或保留相同現存內容。
4. 同一份副本可以接著恢復另一範圍、再次執行；先前的收據保留。使用者改過的檔案會停止且保持原樣。
5. 最後再確認原工作分支、索引、正式採用判決、論文和訓練原件未受影響，H仍至少留1TiB。

全部通過後，把最後實際恢復證據加入總版本附件，再次從GitHub取回核對，才發布最後總版本，並核實其固定來源。若更新預設入口，使用相同已驗證內容，保護原D工作副本。只有此時可說全專案保存完成並刪除本次接續安排。
