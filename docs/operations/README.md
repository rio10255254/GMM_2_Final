# 維護說明

這裡是給維護 repo 的人看的規則。只想讀研究內容，請到[研究入口](../reproducibility/README.md)。

| 我要… | 先讀 |
|---|---|
| 改研究文件前，確認哪一份才是正本 | [正本規則](SOURCE_OF_TRUTH_POLICY.md)、[特殊的路徑與命名](QUIRKS.md) |
| 開一輪新實驗 | [開新實驗指南](STARTING_NEW_EXPERIMENT.md)。請開新資料夾，不要拿舊輪次的資料夾改名重用 |
| 查早期的 Round16 到 31 | [早期批次的規則](LEGACY_ROUNDS_OPERATIONS.md)；當時的決策和檔案位置都照原樣 |
| 找某個檔案放在哪 | [專案地圖](../navigation/PROJECT_MAP.md) |
| 了解 2026-10-28 的資料夾整理 | [整理紀錄](TREE_RESTRUCTURE_20261028.md)：每一階段搬了什麼、改了什麼、怎麼驗證 |
| 規劃以後新增的內容該放哪 | [專案地圖](../navigation/PROJECT_MAP.md)的「新內容歸誰」。整理之前寫的[結構藍圖](PROJECT_FUTURE_STRUCTURE_PLAN.md)留作參考 |
| 查封存的東西和怎麼取回 | [封存索引](PROJECT_ARCHIVE_INDEX.md)、[清掉的副本去了哪](D_DRIVE_FULL_CLEANUP_20261022.md) |
| 查某個大資料夾為什麼還留著 | [保留理由](D_DRIVE_RETENTION_REVIEW_20261022.md) |
| 保存與容量的總原則 | [儲存與封存規則](PROJECT_STORAGE_AND_ARCHIVE_POLICY.md) |

刪東西、搬東西之前，要先有授權，也要逐批核對來源。資料夾名字叫 trash、temp 或 archive，不代表裡面的東西可以刪。正式模型、相機原拍、論文、正在跑的訓練和必要的來源都受保護。舊的整批上傳排程已經停了，不要重新啟動；可以重新生成的大量產物不必再送上 GitHub。
