# R61 boundary generalization progress - 2026-06-23

## Dataset answer

The existing training data should continue to be used. R61 keeps the old data as anchors:

- 800 legacy shape examples.
- 1200 sequence guard examples.
- 1400 SEM-truth real-sample anchor examples.
- 4096 synthetic universal-boundary examples.

The failure was not "old data is useless." The failure was that the first R61 synthetic design had wrong target behavior: dark and bright inputs were both taught to reconstruct the same bright target. That created polarity interference and made dark boundaries unstable.

## Changes made

- Synthetic targets now preserve polarity: dark inputs reconstruct dark sharp targets; bright inputs reconstruct bright sharp targets.
- The same geometry can still be rendered as dark and bright, but only the boundary location is shared.
- Synthetic geometry sidecars are written from known masks, not re-guessed from the rendered image.
- Training packages now use grouped validation splits so the same synthetic geometry cannot appear in both train and validation.
- Bias-mix and subpixel-mix packages were added to test whether the model learns variable boundary correction rather than a fixed 2 px correction.

## Current read

R61 bias-mix is the best balanced candidate so far. It is much better than R60 on 2 px boundary correction and slightly better on average at 1 px, but it still weakens the 1 px dark-boundary case compared with R60.

R61 subpixel-mix is the best low-displacement specialist so far. It is very strong at 1 px for both dark and bright boundaries, but under-corrects 2 px cases.

Therefore, R61 has not yet earned a "general-purpose guaranteed" claim. The next useful design is a hybrid package that keeps subpixel and 0 px guard examples, but over-samples larger 2 to 2.5 px offsets enough to recover the 2 px performance of bias-mix.

## Generalization gate and replay round

A stricter gate was added after the R17-R19 rounds. It compares a candidate against the selected R8 checkpoint on the same 96-case validation and requires no regression on:

- overall mean, p95, and max boundary error
- bright and dark boundary means
- every tested bias level mean
- every tested shape-family mean

This gate is intentionally conservative. It prevents promoting a model that improves the average, or improves only the 0/0.5 px cases, while quietly damaging dark boundaries, large offsets, or thin features.

## Tail-only replay rounds

The next repair attempt changed the training mechanics instead of only changing the data. The model loader now supports freezing most of the network and training only the final reconstruction head. This was added because earlier full-model updates were too easy to over-steer: they could improve one boundary family while moving other boundary families in the wrong direction.

- Existing data is still valuable and should be kept.

- The next data design should keep old-data replay, but make the validation split untouchable and rebalance the train mix around the exact failure bins: 0.0/0.5 px, ellipse-like curves, bright boundaries, and thin/high-curvature regions.

## Boundary-adapter rounds

The adapter starts as an exact no-op when old weights are loaded, so any change comes from training the new branch rather than disturbing the selected checkpoint. The training/inference scripts now preserve the adapter config in checkpoints, and the inference script reconstructs the correct architecture from checkpoint metadata.

R26 trained this adapter from R8 using the shape-neutral replay package. It improved the overall mean and max error, and it showed that a small residual branch can help dark boundaries and large-bias cases. It did not pass because it introduced small regressions in bright boundaries, no-op/small-bias cases, and curved/rotated shapes.

## Boundary-position loss and guarded replay rounds

The next repair added a direct boundary-position objective. This loss penalizes reconstructed edge energy that lands away from the geometry sidecar boundary, while ignoring the artificial image-border edge that otherwise contaminates Sobel-based edge maps. A unit test now verifies that an edge placed on the true boundary scores lower than the same edge shifted away from it.

R30 trained from R28 using the shape-neutral replay package and the new boundary-position objective. The training itself was useful: the latest R30 checkpoint improved the matched 96-case mean, p95, max, dark boundaries, large-bias cases, circles, rotated rectangles, and thin bars compared with R8. However, it also slightly regressed the 0.0/0.5 px guard bins, bright boundaries, and ellipses.

Because R30-latest looked over-strong, a fixed weight-level interpolation was tested. The best interpolation, 25% from R30-latest into R28, reduced the failure count to three and preserved the small-bias bins, but still failed bright boundaries, 1.0 px bias, and ellipses.

R31 started from that 25% interpolation and used the bright-curve replay package with a lower boundary-position weight. It improved the matched 96-case mean again and made the 1.0 px failure almost vanish, but it still failed the strict no-regression gate because bright boundaries and ellipses remained slightly above R8.

R32 introduced a new `bright_ellipse_guard_v9` data profile: old anchors were kept, while the synthetic mix emphasized bright boundaries, ellipses, 1.0 px, and small-bias guard cases. This improved the overall mean a little more, and the ellipse gap became much smaller, but it created additional annulus/polygon regressions. R32 is therefore a negative selection result, not a promoted model.
